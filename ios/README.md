# trade-agents — iOS app

A native SwiftUI client for the existing Flask backend. There is **no new server**:
every screen reads the same `/api/*` endpoints the web dashboards do.

## Status

This is a working vertical slice, not a finished app. It exists to prove the whole
pipeline — project, networking, decoding, native charts — against the live API, so
the remaining work is repetition rather than unknowns.

**Done and verified**

- Xcode project targeting iOS 17+, building for arm64 and x86_64 simulator.
- `APIClient` — an actor over `URLSession`, 30 s timeout, cookies on, URL cache off.
- `Models.swift` — `Codable` types read off the *live* `/api/markets` response and
  verified against it (16 instruments, 12 sectors, dates parsed, nulls dropped).
- `MarketsView` — instrument cards with native Swift Charts sparklines, the sector
  strip, pull-to-refresh, and the server's freshness verdict shown rather than hidden.
- App icon at `Assets.xcassets/AppIcon.appiconset`, generated by
  `build_pwa_icons.py` at the repo root — one definition of the mark for the browser
  tab, the installed web app and this.

**Not started**

- Every other dashboard. `/markets` is 1 of 8, and roughly 100 Chart.js charts exist
  across the web app.
- Sign-in. The backend needs no change — `/login` already verifies a Google ID token
  and replies with a session cookie — but the client needs the GoogleSignIn SDK and
  **an iOS OAuth client ID created in the Google Cloud console**, which cannot be
  done from a checkout.
- `/agents` and StoreKit in-app purchase. Apple requires IAP for the run packs
  (guideline 3.1.1, 15–30%), which also means **products configured in App Store
  Connect**. The web app keeps using Stripe; these are two separate purchase paths
  that must agree on what a user owns.
- Running it, on anything. See "What has and has not been exercised" below.

## Build

```bash
cd ios/TradeAgents
xcodebuild -project TradeAgents.xcodeproj -target TradeAgents \
           -sdk iphonesimulator -configuration Debug \
           CODE_SIGNING_ALLOWED=NO build
```

Or open `TradeAgents.xcodeproj` in Xcode and run.

### What has and has not been exercised

**The Swift compiles and links** for iOS 17+, arm64 and x86_64, in both Debug and
Release.

**The app has never been run, and the app icon has never been compiled.** The
development machine has only the *visionOS* simulator runtime installed, and:

- Launching needs an iOS runtime. `xcodebuild -downloadPlatform iOS` fails in that
  environment (`NFAImageDownloaderError: Unable to decode JSON response`).
- Installing to a paired iPhone needs a signing identity, and there are none —
  that requires adding an Apple ID under Xcode ▸ Settings ▸ Accounts, which cannot
  be done from a checkout.
- **`actool` refuses to compile `Assets.xcassets` at all without an iOS simulator
  runtime**, whatever `-sdk` is passed. So on this machine the build only succeeds
  with the asset catalog moved aside; the catalog is correct and will build
  anywhere a runtime is installed, but that step is unverified here.

So: layout, scrolling, chart rendering and the icon as it actually appears are all
unverified. Install a runtime before trusting any of it visually.

## Notes on the project file

`project.pbxproj` is hand-written — neither xcodegen nor tuist is installed, and a
generator would add a second source of truth. It relies on two Xcode 16+ features to
stay short:

- `PBXFileSystemSynchronizedRootGroup` — the target adopts the `TradeAgents/` folder
  wholesale, so **new `.swift` files need no pbxproj edit**.
- `GENERATE_INFOPLIST_FILE` — no `Info.plist` to maintain; the keys that matter are
  `INFOPLIST_KEY_*` build settings.

`SWIFT_VERSION = 5.0` deliberately. The toolchain is Swift 6.2 and the code is
written to be concurrency-clean, but Swift 6 language mode turns actor-isolation
findings into errors; adopting it is worth doing as its own change, where the
resulting diagnostics can be read rather than fought mid-feature.

## Backend facts that shape the client

- **`/api/fed` is ~1 MB** (211 KB gzipped) — the whole multi-decade FRED bundle. The
  endpoints are shaped for a desktop dashboard that renders everything at once. A
  phone client wants narrower ones, which is server work, not client work.
- **Nulls are the contract, not an edge case.** `pe` is null for a commodity, and
  `prices` carries nulls where a session had no print. The web charts pass
  `spanGaps: true` over exactly these.
- **`meta` is a freshness verdict, and it matters.** `status` separates a live quote
  from a session close from genuinely stale data (see `freshness.py`). The risk in a
  phone app is a number that reads as current because it is on screen, so this is
  surfaced on the markets screen and should be on every screen added later.
